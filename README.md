# 產品型錄網站 V1.2 — iPad／手機 Web 版開發底座

本版依 V1.2 規格重新建立，取代舊版 Windows Tkinter 管理方式。這是**第一階段開發底座**，不是已部署、已驗收的正式網站。

## 目前完成
- iPad／iPhone 響應式繁體中文管理介面（登入頁、儀表板、產品列表、產品新增／編輯表單、分類頁及各模組導覽）。
- Cloudflare Worker API：PBKDF2-SHA256 密碼雜湊驗證、簽章工作階段 Cookie、基本 5 次失敗／15 分鐘鎖定、管理端 bootstrap、產品新增／編輯、分類新增。
- CSV UTF-8（含 BOM）匯出、匯入乾跑與匯入；重複 SKU／不存在分類會阻擋，匯入資料一律建立草稿。
- 多張照片上傳骨架：瀏覽器產生 WebP 展示圖／縮圖、R2 原圖私有保存、公開展示圖需產品上架才可讀取。
- D1 初始資料表遷移：產品、分類、圖片、發布快照、公開圖片白名單、操作紀錄、設定及登入限流。
- 草稿快照檢查、私有管理端預覽、明確二次確認發布；公開 API 只讀取最後確認的快照，編輯草稿不會改變現有公開版本。
- 照片管理：管理者可查看產品現有照片、上移／下移調整順序、刪除照片；刪除時同步清除原圖、展示圖與縮圖。
- 備份：可匯出包含資料表及 R2 原始照片／展示圖／縮圖的版本化 JSON 備份，並在管理端檢查備份檔格式與照片項目。
- 保留公開型錄既有前端資產，後續接上真實圖片與產品 JSON。
- 管理端未連接後端時會明確顯示未連線，不會將示範資料假裝成已儲存資料。

## 部署前必要設定
1. 先由使用者本人建立／登入 Cloudflare 帳號並授權部署；不在聊天中提供密碼或 Token。
2. 確認只使用免費方案；未經明確同意不得升級或啟用付費資源。
3. 建立 D1、R2，填入真正的 D1 ID 與 bucket 名稱。
4. 使用 Cloudflare Secrets 設定 `ADMIN_USERNAME`、`ADMIN_PASSWORD_HASH`、`SESSION_SECRET`。密碼雜湊格式為 PBKDF2-SHA256（310,000 次）；可在可信任的本機 Node 環境使用 `node tools/create_password_hash.mjs "你的長密碼"` 產生雜湊，再只將雜湊存入 Secret。登入端已有基本 5 次失敗／15 分鐘鎖定。正式上線前仍須完成復原流程與第三方安全審查。
5. 執行 SQL migration、部署 Worker，完成權限與免費額度驗證後，才可讓管理者登入。

## 專案結構
- `admin/`：iPad／iPhone 管理介面
- `public/`：公開型錄靜態資產
- `worker/`：Cloudflare Worker API
- `migrations/`：D1 SQL schema
- `docs/`：開發與驗收紀錄
- `tests/`：本地靜態檢查

## 重要安全界線
公開訪客免登入；管理端必須登入。草稿、原圖、備份與管理 API 不可公開。`noindex` 不是存取控制。公開網址可被轉傳與保存。任何尚未通過驗證的登入／發布／備份流程，不得視為正式可用。

## 本地靜態資產檢查（開發者使用）
- `node tools/build_assets.mjs`：將管理介面與公開頁面整理到 `site_dist/`，這是 Worker 靜態資產唯一公開目錄。
- `node tests/check_static.mjs`：檢查 JavaScript 語法與必要檔案。
- `migrations/0001_initial.sql`：D1 初始資料庫結構。

`worker/`、`migrations/`、`tools/`、`docs/` 不會放進公開靜態資產目錄。


## 階段三補強（2026-11-20）
- 備份檢查改為逐筆核對每張產品照片的原圖、展示圖與縮圖物件鍵，並檢查重複鍵與 Base64 格式；不再錯把每張照片的三個檔案當成一個檔案。

- 新增 `photo_upload_requests` 資料表，備份亦包含此表。
- 尚未進行 Cloudflare 真實 D1/R2 整合測試；正式還原仍未開放。
